# Real 4D download integration harness

These are opt-in tests of the production 4D classes, not a Python simulation of
4D callbacks. They have not been executed without an installed 4D runtime.
Use **4D 20+** and a disposable copy of the component project with its declared
`event`, `tcp` and `workers` dependencies resolved. Do not use a primary checkout
or a working database: tests intentionally create/change temporary cache files.

1. Build/stage the matching native package, including `sd-cache`, under that
   copy's `stable-diffusion/Resources/bin/{macOS,Windows}`. Do not use the legacy
   checked-in binaries. Preserve executable permissions.
2. Copy `_DownloadTestOwner.4dm` to that copy's `Project/Sources/Classes/`
   and `TEST_downloads.4dm` to `Project/Sources/Methods/`.
3. Start `python3 scripts/tests/download_fixture.py --port 40480`. It listens
   only on loopback and serves tiny synthetic bytes, not real model weights.
4. Open/compile the disposable project in 4D, enable assertions, run `TEST_downloads` in a worker,
   and require no assertion/compile errors and the final `PASS` debug message.
   Assertions cover real async success, verified-cache bypass, offline receipt
   recovery, corruption/missing files, bad/empty/missing metadata, HTTP errors,
   truncation/wrong length, and duplicate failure/completion propagation.
5. Stop the fixture with Ctrl-C. Temporary test directories are named
   `sd-download-tests-<UUID>` in the OS temporary directory; remove only the
   specific directory generated by your completed test.

The test subclass overrides metadata URLs and queued transfer URLs only.
Production descriptor/hash/queue/HTTP/callback/promotion/receipt logic remains in
use, and inference server startup is replaced by a counter. Loopback HTTP is a
test seam, **not** a production insecure download option. Production CDN redirect
policy is exercised by native helper tests; this HTTP fixture does not test
real HF authentication, public TLS, CDN infrastructure or large model inference.
